# 后台助手

## 功能与运行流程

后台助手把一项独立任务交给父对话下面的一份子对话。子对话使用正常的模型与工具流程执行，主对话可以继续处理其他事情，最后由现有 trigger 把结果带回父对话并触发下一轮回答。

流程是：提交任务 → 返回登记信息 → 主服务接纳并执行子对话 → 等待真实终态 → trigger 回传绑定请求的结果。命令返回时任务通常还未生成，`ok: true` 与 `complete: false` 表示登记或处理中；它不表示工作已经完成。

主服务必须运行。Web 和 Telegram 可以单独关闭，包装脚本不需要网页登录、Cloudflare 验证或 Telegram 二次验证。CLI 负责登记和查询，模型与工具由主服务原有队列执行，父对话不用启动一个长时间等待的命令。

简介中的命令要交给当前调用模式的命令执行工具：Tool call 使用原生命令工具，正则围栏使用原有命令协议。把命令打印在普通回答里不会执行。

## 任务应包含什么

子对话独立保存聊天、工具结果、运行、队列和表单，不会自动复制父对话的历史，也不自动接收技能索引、技能简介或长期记忆。任务文字应包含目标、必要背景、需要检查的文件或资源、已有结论以及期望交付的结果；不能只写“把刚才那个继续做完”。

它默认沿用现有全局模型、人设、基础提示词、工具、调用模式和权限。`--name` 只设置子对话名字，不选择另一模型，也不改变权限。系统只省略技能与记忆的自动注入，不限制它主动读取文件；自身对话历史和任务中明确提供的信息仍可使用。

文件仍使用主实例现有共享目录，没有自动创建独立工作区。需要父子对话配合时，可直接传递真实文件路径；安排并行修改时说明各自负责的文件，避免同时覆盖同一个文件。

## 执行入口与参数

从真实项目根目录运行简介中的命令。文档中的脚本路径相对该根目录，不固定某台机器的用户名或安装目录。包装脚本使用已安装的项目虚拟环境；没有项目虚拟环境时使用当前 Python 环境。

`delegate` 是本技能的正常入口：创建或复用子对话、登记任务，同时登记结果回传 trigger。

| 参数 | 用途 |
| --- | --- |
| `--message '任务正文'` | 直接传递完整任务文字 |
| `--message-file '路径'` | 从 UTF-8 文件读取完整文字，与 `--message` 二选一；适合长文、多行和复杂引号 |
| `--name '名字'` | 给新子对话命名；省略时由现有会话逻辑命名 |
| `--conversation 子对话ID` | 在属于当前父对话的现有子对话中继续；省略则新建 |
| `--parent 父对话ID` | 手动指定所属父对话；默认使用执行环境的 `XGENT_CONVERSATION_ID`，环境未提供时取主实例保存的当前对话 |
| `--request-id 请求ID` | 标识一次请求；省略时自动生成。原任务重试用同一个 ID，新任务使用新 ID |
| `--generation 数字` | 核对父对话的上下文版本；正常在 Agent 中使用环境提供的版本，不需要手动填写 |

名称接受 1–80 个字符。自定义请求 ID 接受 1–128 个英文字母、数字、下划线和连字符。这是现有命令的参数格式，错误信息会明确指出不合法的值。

例如独立核对依赖：

```sh
python3 skill-public/script/background-assistant/background_assistant.py delegate --name '依赖核对' --message '核对 requirements.txt 的依赖兼容性，列出真实检查结果、失败原文和需要修改的项。'
```

长任务先保存为 UTF-8 文件，再提交文件内容：

```sh
python3 skill-public/script/background-assistant/background_assistant.py delegate --name '资料整理' --message-file 'workspace/task.txt' --request-id task-review-01
```

向已存在的子对话继续提问：

```sh
python3 skill-public/script/background-assistant/background_assistant.py delegate --conversation 子对话ID --message '根据刚才的结果继续核对这一项，并给出证据。'
```

需要在同一父对话下安排多项独立工作时，分别调用 `delegate`，为每项工作保存自己的请求 ID。它们按主服务现有队列与运行规则处理，本技能没有额外建立另一套执行器。

## 登记信息、查询与真实结果

首次登记的 JSON 通常包含以下字段；具体 ID 使用实际返回值：

| 字段 | 含义 |
| --- | --- |
| `request_id` | 这一次任务的标识，查询、取消和重试都使用它 |
| `conversation_id` | 执行任务的子对话 ID |
| `parent_conversation_id` | 接收结果的父对话 ID |
| `trigger_task_id` | `delegate` 登记的后台回传任务 ID |
| `status` / `complete` | 当前状态及是否进入终态 |
| `ok` | 命令或当前状态是否正常；应与 `complete`、`status` 一起判断 |

子对话 ID、请求 ID 和 trigger ID 是不同对象，不能互换。父对话继续工作即可，完成后 trigger 会主动回传。用户询问进度或需要排查时，可以主动查询一次：

```sh
python3 xgent_conversation.py status --request-id 实际请求ID
```

手动指定父对话时，查询和取消也应使用同一个 `--parent`。结果按父对话、请求、运行和回复组关联，不能用子对话“最后一条消息”代替这个请求的结果，后来的普通聊天也不会被当成原任务的回答。

完整结果可能包含 `reply`（最终回答）、`replies`（各轮回答）、`tool_results`（真实工具结果及留存路径）、`media`（已保存的附件引用）、`errors`（原始错误），以及队列、运行、回复组标识。

`errors` 中标为 `intermediate: true` 的项是中途操作失败，后续可能已纠正。不要仅凭出现过中途错误就把整次任务说成失败，也不要忽略失败原文宣称全部通过；结合终态和实际结果逐项判断。

图片、文件及工具存档使用返回的真实路径核对。文件也可能通过工具结果携带路径，并非都出现在 `media` 字段。需要向用户交付文件时，使用现有文件发送工具；保存文件、返回路径和发送文件是不同步骤。

## 状态与表单等待

| 状态 | 如何理解与处理 |
| --- | --- |
| `pending` / `queued` | 已登记或排队，尚未完成；主对话继续工作 |
| `running` | 模型或工具正在执行，已有中间结果不代表结束 |
| `waiting_form` | 子对话等待用户填写表单；进入对应子对话完成表单后原请求继续，回传不会提前冒充完成 |
| `completed` | 已正常结束，结合返回的回答、工具结果、文件和中途错误核对成果 |
| `failed` | 执行失败，读取 `error` 与 `errors` 中的真实原因 |
| `stopped` / `cancelled` | 已停止或取消，已有结果可保留，但不称为正常完成 |
| `interrupted` | 接纳或执行被中断，例如主进程重启；不会自动重复发送任务或重跑工具 |
| `invalidated` / `withdrawn` | 所属上下文失效或任务输入已撤回，结果不会转投其他对话 |
| `empty` | 已进入异常终态，没有正常完整结果，应按返回信息处理 |

以接口实际返回的状态和 `complete` 为准。表中未列出的队列状态也应按实际值报告，不猜成成功。

父对话清空或手动压缩后，已登记任务仍属于同一父对话，结果进入它的新回合。清空子对话会使对应任务失效。挂起表单的进程重启恢复不在本技能范围内，重启后中断状态不能当成已提交或正常完成。

## 取消与重试

取消指定请求：

```sh
python3 xgent_conversation.py cancel --request-id 实际请求ID
```

取消会停止该任务的后续执行与回传，并对仍运行的请求发出停止要求。它不删除保存的子对话，也不回滚已经执行的命令、文件写入或外部操作。需要删除子对话时，使用现有会话删除操作。

提交响应丢失、需要确认有没有接纳时，先查询已保存的请求 ID。重试提交同一项任务时复用原 `--request-id` 和相同任务文字、父对话、来源技能及目标子对话，已登记的请求不会再创建或执行一遍。

同一个 ID 对应另一项任务时，命令会报“请求标识已用于另一条任务”。这时核对原任务；如果确实是另一项新工作，使用新的请求 ID。修改任务内容后再发送也属于新请求。

`wait` 是 trigger 使用的后台等待入口，普通父对话不直接运行它持续阻塞。它支持 `--timeout 秒数`；超时只结束这次等待，不取消任务、不重发任务，也不表示生成失败。它的用途是诊断或由后台调度处理，不代替简介里的非阻塞 `delegate`。

## 故障排查

| 现象或原始错误 | 核对内容 |
| --- | --- |
| 找不到包装脚本或 `xgent_conversation.py` | 核对真实项目根目录、技能文件路径和配套脚本是否安装完整；命令路径不要套用另一台机器的安装目录 |
| Python 模块缺失 | 核对当前主实例的 Python 环境和 requirements；包装脚本会优先采用项目虚拟环境 |
| 任务内容不能为空、文件不可读或 UTF-8 解码失败 | 检查 `--message` 内容，或 `--message-file` 的真实路径、文件编码及原文；多行任务使用文件避免引号改写 |
| 父对话不存在或已归档 | 核对 `--parent` 和执行环境；需要使用该归档对话时先恢复它 |
| 父对话上下文已改变 | 新任务使用当前上下文版本重新提交，不把旧版本数字当成当前版本 |
| 目标不是这个父对话的可用子对话 | 核对 `--conversation` 的真实归属、是否已删除或归档；用下文的 `list` 查看所属子对话 |
| 该技能已关闭，未创建后台助手任务 | 查看主实例中“后台助手”的技能状态；关闭和隐藏都会停用本包装入口 |
| 一直处于登记或排队状态 | 核对主服务是否运行、现有队列是否暂停及任务状态；仅打开网页或运行登记 CLI 不会代替主服务执行模型 |
| 正在等待表单 | 进入实际执行任务的子对话完成表单，随后沿用原请求继续；不要重复派发相同任务 |
| 子对话已完成但父对话未收到结果 | 查看请求结果和 `trigger_task_id`，再核对现有 trigger 的执行、取消及投递状态；区分生成完成与结果投递，不重新创建原任务 |
| 任务记录不存在、输入已撤回或接收记录未恢复 | 核对请求 ID、父对话及撤回或重启情况；不猜另一个运行的结果，也不直接重复已执行的操作 |

查询当前父对话下面的子对话，或核对脚本支持的参数：

```sh
python3 xgent_conversation.py list
python3 skill-public/script/background-assistant/background_assistant.py delegate --help
```

## 子对话、通用命令与技能开关

子对话显示在父对话下方，可以正常查看、继续聊天、重命名、归档和删除；删除父对话会一起删除所属子对话、任务及结果回传，删除某一个子对话保留父对话与其他子对话。共享磁盘文件和全局用量统计不随对话删除而回滚。

通用的 `xgent_conversation.py create/send/delegate/status/wait/cancel/list` 不属于这个技能独占。`create` 只新建空子对话；`send` 只登记发送，省略 `--conversation` 时也可新建；`delegate` 在发送的同时登记 trigger 回传。通过其他技能或手动使用这些通用功能，不要求开启“后台助手”。

本技能的包装脚本标记任务来源。关闭或隐藏本技能会阻止包装脚本的新任务，并停止本技能尚未完成的任务与回传；重新启用不自动重跑旧任务。已保存的子对话仍可查看和正常使用，通用会话功能保留。
