# 新对话延迟保存

点击「新对话」只进入空白输入页，地址为 `#/chat`。打开首页、刷新空白页、填写草稿、选择分组或添加待发附件都不创建对话。不存在或已删除的 `conversation` 链接会自动替换为这个空白地址，包括带消息定位参数的链接。

首次发送文字、附件或已有斜杠命令后，服务器持久接收输入，网页才显示 `#/chat?conversation=<id>`。地址更新使用替换操作，浏览器返回不会落到一个已完成发送的空白中间页。对话保存到发送时选择的分组，后续消息继续使用同一个对话。

普通文字和附件的首次接收在一个数据库事务中完成对话创建、请求映射及队列保存。任何一步失败都会回滚，输入和可重试的附件留在新页面，不留下空对话。模型生成失败时，已保存的对话、用户消息和原有错误处理继续保留。

大文件先完成分块上传，收到完成接纳的回执后才创建对话；上传过程不创建对话。附件原件、说明、顺序和附件／服务器上传模式仍经既有文件接纳、队列与模型请求构造处理。

新页面和已保存对话分别保留输入草稿。首次文字发送使用浏览器草稿标识和请求标识去重；HTTP 回执丢失后，刷新并重试相同文字会返回同一个对话和队列项。保存回执携带对话列表版本，早于此次保存的列表或同步回执不会清空新对话。用户已切换到其他对话时，迟到的成功回执不会抢走当前页面。首次附件失败可以在当前页面重试；浏览器刷新后需重新选择本地文件。

空白页不读取共享默认对话的历史，也不展示其他对话的流式消息或运行状态。首次发送只更新共享默认选择，Telegram 的当前对话选择保持原有独立行为。上下文、工具执行、表单、回复方式和后续消息处理继续调用既有服务。

从空白页进入设置后，创建后台任务可以选择一个已保存的来源对话；创建任务不会保存空白页。分支和子对话继续使用原来的显式创建流程，保留快照、父子关系与原有功能。

验证使用隔离 SQLite、真实 Web 接纳入口和浏览器，模型与 Telegram 传输使用测试替身。覆盖空白页和无效链接、首次文字、普通／分块附件、失败回滚、丢回执重试、独立标签页、分组、设置返回、任务来源及原模型上下文隔离。数据库 schema 仍为 11，无额外迁移。
