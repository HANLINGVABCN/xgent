# 附件不可用、错误结束与长对话显示

Git 历史确认普通上传附件曾做过容错：`4359e03`（2026-10-15）加入“暂不可用”表示，`cfcf0a9`（2026-10-23）接入版本读取，`c2f652c`（2026-10-25）扩展统一文件入口。生成图片的固定原件校验和 read 工具的冻结副本恢复仍有单独的失败分支，普通上传的容错没有覆盖这两处。

普通对话现在逐个处理缺失、不可读或被改写的历史原件与工具副本：向模型明确提供文件标识、路径和“附件暂不可用”，继续提供其余文字、图片及实际工具结果。文件恢复且校验通过后自动恢复内容。生成原件被替换时保留原指纹，不把新文件冒充旧图。原始消息、附件关联、工具调用与结果、导出记录不改写；显式严格校验和不安全的关联仍按原规则拒绝。

read 的独立记录保存当时的真实结果，供后续模型、历史及导出使用，不是额外发给用户的文件卡片。现在文件副本失效只影响该附件，文字结果和调用关联保留，不再卡住整个聊天。

Web 在真实错误结束后也会收起连续至少两轮的纯命令回复。结束事件同时匹配回复组与运行 ID，终止错误留在折叠外，中途操作失败的原始输出保持原位置，不增加失败汇总。同一回合的模型错误参与头像去重，只在该回合开头显示一次 XGent；独立错误仍显示头像及已记录的提供商、模型。正文继续使用原始普通文字，保留现有报错限制和模型可见性。

阅读旧记录期间保留本次已加载的历史，分页只追加相邻记录，不按 200 条阈值自动移走旧消息、整段命令或报错。明确返回最新、手动重载、切换会话或改变历史版本时才替换阅读窗口，释放相应节点和本地预览；最新消息模式继续使用原有回收预算。历史仍分批请求，网络预取缓存仍有界。

展开按钮变成零高度的控制点后仍恢复点击位置，避免跳过锚点；由程序恢复的位置不作为用户滚动方向。滚动容器关闭浏览器的额外自动锚定，统一由现有位置恢复处理。鼠标、触摸和键盘提供翻页方向，后台预取不再单凭位置恢复就连续插入历史页。

连续翻页时，已结束回合的标记独立于末尾回复是否仍挂在页面上；同一命令段补齐较早轮次时复用已有折叠状态，保留展开操作。两个分页方向的游标跟随实际保留的窗口更新，记录保持连续。定位到折叠内的消息会展开对应段，再定位到真实消息。

网络重连按当前阅读位置请求附近记录，保留同一数据版本下已加载的连续窗口及滚动位置，不改成最新一页，也不把远处的新回复插到旧记录后造成空洞。切换会话、清空、撤回、手动重载和返回最新仍更新对应窗口；阅读锚点已被删除时按明确的 404 结果重取当前历史，网络失败不按“记录被删除”处理。

send_file 的 Telegram 原文件发送不改变。Web 按媒体类型显示图片、视频、音频预览，图片大图查看和下载使用原件；文本文件复用现有按会话授权的分页预览。发送结果保存后立即同步稳定附件标识、文件名及路径，实时画面与刷新使用同一份预览信息。不可预览的二进制保留下载，缺失提示仍为原有小号红字。

验证使用模拟上游、临时附件和本地隔离浏览器，覆盖文件删除、改写与恢复，原始工具结果及错误保留，错误折叠、阅读记录保留、头像、图片及文本预览。没有连接、修改或重启服务器。对话中“一秒后 DNS 自动恢复”的说法未取得服务器证据；仅凭 `Name or service not known` 可以确认解析失败，不能确定持续时间。
