# 渲染页面与 Telegram Web App

开启 Agent 后，可以要求“做一个图标并展示效果”“把这段 HTML 渲染出来”或“做一个能切换选项的演示页面”。模型调用 `render_visual` 创建页面，网页对话直接在隔离 iframe 中渲染 SVG／HTML。CSS、动效、内联 JavaScript 与页面内交互均可使用；不需要服务器常驻浏览器，不生成效果图片。

Telegram 使用普通可展开折叠块显示源码。折叠不减少 Telegram 的字数占用；源码超过单条消息的安全预算时，正文明确写“源码节选 · 完整源码见附件”，同时发送完整 SVG／HTML 文件，不用“已折叠 × 行”替代缺失内容。已启用 Web、配置访问密码和 HTTPS 公开地址时，源码消息附“打开渲染页面”Web App 按钮，沿用现有 Telegram 登录能力，定位同一对话、同一记录并展开同一个网页渲染组件。

工具接受 `format`（`svg`／`html`）、`source`（完整自包含源码）、初始 `width`、`height` 和可选 `title`；正则围栏模式用 `render-x`，正文为相同字段 JSON。源码最大 256 KiB，初始尺寸每边 64–1600。页面源码和校验信息关联原有消息，刷新可读取；完整文件下载按对话与记录授权，撤回、删除或源码变化后旧入口失效。

iframe 使用独立来源沙箱，仅允许脚本运行；宿主 DOM、Cookie、对话状态、网络请求、子框架、外部脚本、CDN 与本地文件不可访问。图片等资源可内联为 data/blob，CSS 和 JavaScript 写在页面源码里。普通页面内交互不自动提交到模型，原有对话构造保持不变。

表达指导集中在 `global_addon.txt`：需要看效果时展示页面，正文简洁，不重复源码；Telegram 的折叠代码不冒充网页。工具参数留在工具定义和正则围栏提示词。旧版全局默认提示词仅在原文完全匹配时自动备份升级，自定义修改不自动覆盖。本次不引入栅格渲染依赖。
