# Web 设置响应速度与排版

设置页的基本控制先显示，备份、两步验证、系统状态和尚未读完的头像库分别加载。某个面板等待或报错时，其他设置仍可使用；报错面板保留重试。已有页面更新时保留当前内容，等新数据读完再替换，编辑中的表单继续保留。

## 卡顿来源与处理

此前 `/api/config` 和工作台初始化都会返回完整的 Base64 头像库，每次设置切换还会重复读取初始化数据并重新序列化响应。初始化逐项查询设置，也包含头像库这种大字段。

现在一般配置和设置事件只包含品牌版本号。头像内容由 `/api/branding` 单独读取，版本未变只返回短的 `unchanged` 响应。品牌与字号使用独立版本号，字号变化不重新校验、解析或传输头像库。旧数据库沿用已有品牌设置并在写入时初始化独立版本号；备份、导入和跨设备品牌同步继续保留完整配置。

工作台初始化批量读取所需设置，排除头像库。设置标签复用最多 60 秒的初始化快照，缓存访问不会延长有效期；设置和模型修改、退出登录会使对应缓存失效。

备份估算需要列出文件、统计分类记录，并对最多 1 MiB 的数据实际测试 ZIP、Zstd、XZ 压缩。这项工作仍在原来的后台线程执行。相同抽样现在复用压缩率和时间测量，避免反复进行 XZ 高压缩计算；文件清单、大小和抽样内容仍重新读取，样本变化会重新测量。每个备份服务最多缓存八组哈希与测量值，不额外缓存原始文件内容。实际导出、导入、校验、权限和压缩级别保持原样。

两步验证状态只读取本地配置，没有证据说明其计算本身很慢。此次没有缓存或绕过登录校验；改动只让状态请求不挡住服务入口等其他控制。

## 本地测量

2026-11-04 使用隔离的回环服务测试。头像库包含三张各 1 MiB 的合成图片数据，当前头像为默认 b；每个接口连续读取六次。没有连接部署服务器、真实模型或 Telegram，也没有读取用户密钥文件。

| 读取内容 | 修改前响应大小 | 修改后响应大小 | 本地平均耗时：前 → 后 |
| --- | ---: | ---: | ---: |
| 普通配置 | 4,197,069 字节 | 2,359 字节 | 149.36 → 19.81 毫秒 |
| 工作台初始化 | 4,199,841 字节 | 5,136 字节 | 212.25 → 34.39 毫秒 |
| 完整头像库 | 4,194,745 字节 | 4,194,745 字节 | 200.31 → 175.40 毫秒 |

完整头像库仍需按需读取，图片未删除或缩减；版本未变时响应为 34 字节。以上耗时受测试机器与并行测试负载影响，响应大小更能说明减少重复传输的效果。

另用一个 1 MiB 的合成文件测试备份估算。重复五次的平均时间从 486.27 毫秒降至 4.91 毫秒；第一次计算为 497.03／542.80 毫秒，仍需要扫描和实际压缩。大量文件或远程磁盘的首次扫描可能更久，前端只让对应面板等待。线上改善程度需要更新后实测。

## 消息排版与验证

头像与名字的布局恢复到此前的设计，大小保持 24px／15px 加粗；正文、思考、媒体和尾注沿用原来的左侧位置。报错消息的提供商和模型仍紧跟名字，原始错误文字保留。

实时事件批量更新结束后统一整理头像与命令关联，再恢复阅读位置，避免同一批事件反复扫描全部消息。历史翻页、折叠和已加载记录的保留规则不变。菜单和弹窗使用短幅度动效，减少动效设置仍生效。

本地浏览器验证覆盖桌面、手机、延迟与失败的可选面板、缓存失效、编辑保护、头像保存与旧读取竞争、原始报错和历史阅读。备份验证覆盖原有格式、分类选择、导入回滚和独立 Bot 使用；这些是模拟接口与本地浏览器验收，不能代替真实模型或线上性能验收。
