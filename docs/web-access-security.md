# 网页访问安全与登录设备

设置 → Web 与安全可查看近期 IP 的访问次数、认证失败次数、最后活动和封禁状态，以及已封禁 IP／设备列表。登录设备支持查看浏览器、来源 IP、登录时间、最近活动和到期时间，可踢出指定设备或其他设备。

默认连续认证失败 5 次等待 180 秒；等待期间的请求不增加次数。等待结束后再失败 3 次，立即封禁关联 IP 和设备，并撤销关联登录。完整登录成功会清除连续失败计数，历史失败次数保留。规则可在后台修改。限速、封禁、名单和设备登录都保存在 SQLite，普通更新、PM2 或 Web 重启不会清空。

封禁后生成“来自网页端的未授权请求”卡片，与电报陌生人卡片区分来源。卡片沿用现有告警的对话记录、模型上下文和跨端通知路径，并在网页弹出提醒。Telegram 卡片的“解除 IP 和设备封禁”同时解除该次关联的两种封禁；解除后仍需正常登录，不恢复已撤销会话。没有可用的 Bot 会话时保留全局安全事件并通知 Telegram，不把卡片分配到任意其他对话。密码、验证码和 Cookie 不会进入告警或访问日志。

IP 黑名单拒绝访问，支持单 IP 和 CIDR 网段；白名单仍要求正常密码／两步验证，但跳过自动等待和封禁。手动封禁的 IP／设备须先解除，黑名单优先于白名单。

默认使用实际 TCP 来源 IP，不信任浏览器自行提供的代理头。使用本机 Cloudflare 隧道时，可选择 CF-Connecting-IP；使用本机反向代理时，可选择 X-Real-IP。只有本机来源连接且明确选择的头才用于来源识别；代理必须覆盖该头，后端不得对外直连。不要把所有经过代理的访客误识别为代理的 IP 后再封禁。

设备由 HttpOnly 签名 Cookie 标识，不使用浏览器指纹。清除 Cookie、无痕窗口或换浏览器可能生成新设备，所以设备封禁与 IP 封禁共同使用。设备列表展示登录会话，不声称可识别物理硬件。旧版有效登录会自动升级为可单独撤销的设备登录；每台设备再次登录会撤销旧登录，避免重复设备记录。

登录默认启用自动续期，服务端按最后一次有效使用计算到期时间：连续 30 天未使用才需要重新登录，正常使用不会每隔七天强制重登。设置 → Web 与安全 → 已登录设备可调整为 1–365 天或关闭自动续期；关闭后不继续延长现有授权，新的登录按设置期限固定到期。缩短期限会限制现有有效会话的剩余期限，延长设置不会复活已到期或被撤销的登录。

续期保留同一个设备和会话 ID，不创建重复登录记录；已有效的旧七天会话在下次使用时沿用新规则。签名 Cookie 按需节流刷新，避免每条请求重复签发；数据库精确记录每次有效使用的到期时间，Cookie 额外的短传输缓冲不延长服务端授权。聊天和终端 SSE 建立时可下发续期 Cookie，之后的后台心跳鉴权不计作有效使用、不延长会话。普通更新与重启保留签名密钥及设备记录；踢出、退出、封禁、改密和两步验证变更仍使相应授权失效。未完成的两步验证绑定使用稳定的已认证会话关联，不因 Cookie 自动续期而失效。

访问日志和封禁事件属于备份的安全日志，IP 规则属于应用设置，设备会话属于运行状态，签名密钥属于密钥与凭据。网页终端进程仍不会跨服务重启恢复或自动重跑。
