# 前端重写：功能基线与架构

此次改版以本地已有修改后的版本为基线。允许重新设计视觉与导航、页面布局和组件层级；构造对话的逻辑、每个组件的能力和信息完整保留。回退副本与改版前截图保存在本地 `workspace/frontend-rebuild/baseline/`、`baseline-shots/`。

最终结构只有「对话」与「设置」。新对话下面没有额外的四个管理快捷入口。对话列表采用紧凑行，折叠按钮位于列表顶部，收起后保留可直接展开的窄栏，分支与子对话使用统一的徽标和树形连接线；设置中 13 项使用同一个常驻导航，十一项内容面板共享显示区域，全局搜索和退出保留原有操作。切换设置内容不改变 `#/settings` 地址，导航节点持续保留。旧管理地址仍可打开对应设置面板，原 API 和对话服务不变。

「新对话」使用可拖拽的真实链接，支持拖到标签栏、Ctrl／⌘ 点击和中键打开空白页；普通点击继续使用页内新对话逻辑，不提前创建记录。其他对话运行时只在列表显示生成标识，移除常驻运行横幅。观察到其他对话结束后显示一次完成通知，八秒后自动关闭，右上角可手动关闭；当前对话和主动停止的任务不重复提示。进入运行中对话时暂时缺少的用户消息操作，在结束后按记录 ID 补齐，无需刷新或重建消息正文。

设置的「系统状态 → 版本与更新」可检查主仓库／测试仓库、使用已配置或本次填写的 GitHub Token，并确认是否覆盖本地提示词与公共技能；默认保留，覆盖前沿用原服务备份。检查结果固定到对应提交，确认后复用原下载及重启服务，数据库、环境配置、运行数据和私有技能保持原有保留规则。进度持久保存，重启后核对代码版本；重复请求不会执行两次，忙碌对话期间拒绝更新，失败不继续重启。本次填写的 Token 仅在本次更新检查与执行中使用，不回传、不写入任务记录。

首页对话列表底部的归档入口已移除；归档管理统一从设置打开，保留恢复、导出及所有对话操作。

点击「新对话」打开地址为 `#/chat` 的空白页。首次文字或附件被持久接收后，才创建对话并将地址替换为实际对话链接；不存在的对话链接自动回到空白页。原有对话与新页面各自保留草稿，设置中的任务可选择已保存的来源对话。保存、重试及上下文隔离见 [新对话延迟保存](new-conversation.md)。

归档改为隐藏系统分组，名称不可修改、不创建分支，但可以继续对话和建立子对话。父子树集中展示在设置的归档列表中；原分组与置顶信息保留，父对话恢复时子对话一起恢复，并自动进入父对话。详细交互与迁移见 [归档分组](archive-group.md)。

外观提供 a 流光蓝紫、b 终端雾蓝、c 黑曜钛金、d 黑白极简、e 冷暖对撞、f 黑客翠绿六套独立主题，各有明暗两版。主题和头像独立选择；默认是原图 b 的蓝紫款（新编号 a）。原预设 ID 保留，顺序调整不改变已保存的头像。界面配色和明暗模式保存在本浏览器，并同步同源标签页与内嵌终端；头像继续使用原服务端配置。

顶栏为桌面 46px、手机 44px，移除路径提示和品牌副标题。分支对话只显示与消息分支按钮相同的图标。输入栏移除独立 Agent 按钮，思考档位简化为自动、简短、标准、深入。弹窗点击外部关闭，未保存编辑仍保留既有确认；对话“移动到”沿用桌面悬停、手机点击的分组子菜单。

搜索、草稿与业务配置输入统一关闭浏览器历史填充，并标记为密码管理器应忽略的字段；工具密钥使用新密钥语义。登录密码与验证码放在独立登录表单中，保留原有填充和提交行为，避免浏览器将侧栏搜索当成账号框。侧栏另监听浏览器的自动填充状态，恢复用户明确输入的查询，不让误填内容发起搜索。正常编辑、中文输入、清空和草稿恢复继续使用原逻辑。专项浏览器测试覆盖 Chromium 自动填充状态、动态搜索、提供商、表单、登录与终端；扩展自行注入内容仍取决于其是否遵守忽略标记。

新建或编辑提供商均可用当前表单的连接信息拉取候选模型，拉取不保存配置或回显服务器密钥。忙碌期间的附件和服务器上传可以完整入队；等待期间的附件不进入模型上下文，领取时使用原有附件记录与请求构造逻辑。取消／取回会恢复原件、说明、顺序和接入模式，大文件分块与普通上传都保留入队参数。见 [附件排队](attachment-queue.md)。

## 分层原则

共享设计变量集中定义，各组件 CSS 分别拥有自身布局。`navigation.js` 统一定义并生成设置导航；`settings-content` 只挂载当前内容，复用缓存中的原 DOM、筛选和滚动位置。任务、文件、模型按需加载，纯消息呈现在 `chat-view.js`，通用控件在 `ui.js`。对话上下文构造、工具调用、任务执行、认证及同步沿用现有服务和协议。脏表单保护、异步取消和来源定位继续保留。

历史读取通过 `history-loader.js` 统一处理截止时间、有限重试和不完整响应，仍按需补齐分页，保留当前阅读记录。翻页和长命令展开后的布局变化会短暂跟踪阅读锚点；用户继续滚动、触摸或操作时立即让位，不锁定滚动。发送中的文字与附件作为本地消息保留到持久记录接替，接收标识参与实时和刷新同步的合并；实时通道断开不取消独立上传。接收、排队、模型调用及上下文构造继续复用原服务，详见 [文件接收](file-ingress.md)。

验证使用隔离服务器与现有浏览器回归，不使用实际模型或 Telegram 执行演示操作。每轮验证后的修改同步至 `/home/hanling/xgent-telegram-test/`，重启 `xgent-telegram` 并检查 Web 与 PM2 状态。

`python tools/frontend_rebuild_qa.py` 检查 1440、768、390、320 四种宽度的明暗主题、全部设置面板、代码展开、文件预览、任务/模型表单、输入选项、字号边界、登录和终端，并输出截图与耗时报告。`python tools/deploy_frontend_wsl.py` 保存部署回退副本、校验文件、同步并重启 PM2。

备份目录中的真实条目使用独立的纵向内容组件，文件名完整换行，类型、大小、日期、文件数量、内容分类和下载各自排布。长文件名在 320、390、768、1440 宽度及默认／最大界面字号下均检查无横向溢出；勾选删除和点击扫描依旧使用原行为。

选中压缩包后，导入区始终列出全部内容分组。压缩包未包含的组置灰、禁选并明确标注；展开分组可以核对每个成员是否包含。全选、默认选择和实际导入请求只包含本压缩包可恢复的内容，空内容但明确包含的分类仍可选择。
