# 电报生成状态

原生电报投递保留实际回复模式，生成中的同一条临时状态显示：

- 前台流式：`前台流式输出中… 等待首段内容`，收到正文后更新为 `前台流式输出中… 已生成 N 字`。
- 后台流式：`后台流式输出中… 等待首段内容`，收到正文后显示累计字数；正文继续在完成后统一发送。
- 非流式：`非流式输出中… 等待完整回复`。

前台 Rich Draft 和旧接口预览均保留模式；旧接口在状态下面显示原有完整预览。状态复用原来的消息与停止目标，相同提示不重复编辑，流式预览和后台进度继续按原来的频率控制。结束或停止后沿用原有定稿与清理，不重放过期预览。

模式取自本次回复已冻结的投递策略。状态只在电报出口生成，不写入对话上下文，不改变网页消息、模型请求、原始正文、工具操作或生成模式。

验证覆盖三种模式的实际对话流程、网页与电报独立模式、多轮定稿、表单、压缩、停止目标和限流重试。14 项原生状态核心检查在 Windows 与 Debian WSL 都通过；相关回归的问题修正并复测后无失败，报告保存在本地 `workspace/frontend-rebuild/telegram-release-44.xml`、`telegram-final-45.xml` 和 `linux-telegram-status-46.xml`。
