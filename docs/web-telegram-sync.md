# Web 与 Telegram 同步修复

## 图片投递

Telegram 话题编号属于消息数据，不能作为 `Bot._post()` 的传输选项。本次修复把话题、静默等路由字段留在请求正文，上传层只接收超时选项；原生富文本和旧接口媒体发送都使用同一规则。

生成媒体记录更新当前回复归属，上传得到的 Telegram ID 和 Web 实时 ID保存到实际图片记录中，避免挂到前一条工具请求上。刷新、续接、补投与撤回读取这份关联。三种回复方式继续使用原有媒体生成和投递服务。

## 撤回范围

网页撤回按当前对话的“此消息及之后”范围移除记录，并把已经核对的 Bot 原消息、AI 续段、协议输出、媒体和表单 ID 投到现有删除队列。网页管理操作的普通镜像限制不再拦截经过授权的删除。重复删除已经不存在的同一消息视为完成。

关联保存 Bot 身份、聊天、会话和记录 ID；读取时核对归属，逻辑 ID 也不能被另一会话接管。创建分支清除来源消息的投递关联，旧分支已经复制过来的关联也不用于删除来源消息。拼接的 Telegram 文本保留每个实际输入消息的 ID。

旧记录没有可靠 ID 或 Telegram 拒绝删除时，页面会提示未能同步的范围；程序不猜测邻近消息，也不回滚命令或磁盘文件。

## 思考显示

思考正文不再继承深色代码块的浅字色，标题、正文与边线使用当前主题文字色。字体、折叠、0 秒显示和思考原文保持原规则；用户展开思考后复制页面内容仍能包含该内容。

## 验证

隔离测试运行真实 Web Agent 投递链路与 SDK 上传序列化，覆盖三种回复方式、话题上传、媒体关联、A/B 会话、分支历史、重复删除、Bot 原消息和各类后续记录。浏览器测试核对桌面与手机、亮色与暗色的思考文字对比度。模型和 Bot API 返回采用固定测试数据，没有在用户服务器部署，也不代替真实 Telegram 客户端验收。
