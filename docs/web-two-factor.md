# Web 两步验证（2FA）

默认关闭。在 **设置 → Web 与安全 → 两步验证（2FA）→ 添加验证器** 中手动开启：重新输入当前访问密码，用验证器 App 扫二维码或录入密钥，再填写六位动态验证码。验证成功才启用；生成二维码并不会改变登录要求。

- 使用标准 TOTP，SHA-1、六位数字、30 秒更新；支持服务器时间前后一个周期的偏差。同一动态码不能重复使用，提示已使用时等待验证器下一码。
- 保留原有密码登录限速，第二步另有账号级失败限制；不能通过换 IP 或重开密码第一步不断重试验证码。
- 启用后，网页和独立网页终端的密码登录分两步；第一步不签发登录 Cookie，通过动态验证码或恢复码后才进入。此前的浏览器 Cookie 会失效，完成设置的当前浏览器刷新授权继续使用。
- **电报不增加二次验证。** Bot 的授权方式不变，签名有效且用户 ID 已授权的 Telegram 免密入口仍可直接登录。普通密码请求不能通过一个“来自 Telegram”的标记跳过验证。
- Cloudflare 邮箱验证保持原样；2FA 是 XGent 自己的密码登录验证，不更改域名、代理或外部登录策略。

## 恢复与管理

启用后提供十个恢复码，每个只能用一次，页面仅在本次显示。可以复制或下载保存；登录验证码输入框也接受恢复码。安全页可重新生成恢复码或关闭 2FA，均需当前密码及有效动态码／恢复码。重新生成后原恢复码失效。

遗失验证器但保留恢复码时，先用恢复码登录并在安全页重新配置。两者都遗失时，有服务器本地管理权限的用户可在项目目录执行：

```bash
python3 tools/xgent_config.py reset-web-2fa
```

该命令只重置 Web 的 2FA，不更改访问密码；旧浏览器登录会失效。网页没有无需凭据即可重置的入口。

验证码登录挑战和未完成绑定保存在进程内，五分钟过期，重启后需重新输入密码／绑定；已启用的验证器配置保存在数据库，重启不丢失。验证器密钥属于专用安全配置，恢复码只保存散列。它们不进入消息、模型上下文、普通设置读取或对话导出；整套迁移时属于“密钥与凭据”数据。

已经完成的网页登录默认在使用中自动续期，连续 30 天未使用才需重登；已登录设备设置可调整有效期或关闭自动续期。普通代码更新、PM2 重启和 Web 服务重启会保留有效登录。签名密钥保存在实例数据库的专用凭据项，不回传到网页或模型；访问密码、Bot 身份、授权用户或两步验证版本变化会使旧 Cookie 失效。主动退出仍清除浏览器登录，未完成的两步验证流程不跨重启保留；使用中刷新 Cookie 不会打断正在绑定的验证器。首次从旧版本切换到持久签名时，需要重新登录一次。

## 验证范围

自动检查包含 RFC 6238 标准向量、密码和动态码验证、过期／重放／并发提交、恢复码一次使用与重建、密码变更、旧 Cookie 撤销、Telegram 免密豁免、同源校验、浏览器绑定与密码两步登录，以及原登录／终端回归。浏览器检查使用隔离的本地服务器和临时验证器配置；不代表已在用户服务器部署或使用用户手机实际绑定。
