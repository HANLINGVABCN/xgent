# 上下文、工具结果留存与对话导出

[返回使用文档](README.md) · [返回项目首页](../README.md)

模型上下文、可见聊天历史和实例备份是不同层次。`/clear` 重置模型上下文；`/compress` 用已完成的摘要替换有效上下文；`/export` 导出对话记录。归档对话的隐藏分组行为见 [归档分组](archive-group.md)，整套实例备份见 [数据管理](data-management.md)。

## 工具结果留存与记忆深度

「工具结果留存」沿用原「read 留存」的配置值（`readx_persist_context`），已开启的用户无需重新设置。开启后，read、run、搜索、文件操作、shell、媒体及表单结果分别保存实际回传模型的内容和界面展示内容；新提问或重启后，不再用展示卡片、简短 notice 替代完整工具结果。关闭只影响之后产生的结果，不删除已经留存的内容。

- 文本工具结果遵循记忆深度；读取到的原生图片和二进制保存不可变副本及校验信息，跨普通文本窗口提供。这些**工具快照**与可编辑上传附件不同：原路径文件后来变化，不改变已读取的版本。副本缺失或校验失败会明确报错，不静默省略。
- 记忆深度的单位是**模型可见消息条数，不是问答轮数**。token 提示、Agent 状态等纯 UI 记录不占名额。只有有效消息超过设置值，才淘汰窗口外的文本消息；窗口淘汰不删除数据库历史；压缩或清空上下文后，可见历史继续保留。
- 原始模型用量统计不改写。模型切换、供应商计数口径或正常窗口淘汰仍可能导致输入 token 减少，不能据此要求 token 数字严格递增。

## 上下文压缩与导出

Telegram、Web、CLI 共用 `/compress` 和「压缩上下文」按钮。流程是**先导出备份，再将压缩指令接在当前历史最后，完整摘要成功保存后才替换上下文**。Agent 关闭也能压缩；已有请求执行中时拒绝插入压缩，摘要中的 Agent 协议不会执行。

- 压缩与 `/export` 使用同一导出服务，保存完整持久化记录，不受普通记忆深度限制。待执行任务和已完成归档链分开保存；导出和模型调用期间不清空对话、镜像或附件关联。
- 压缩请求包含当前有效对话、实际工具结果、文本附件和原生图片/二进制。最后追加一次当前压缩指令；普通系统提示词为空，不额外注入人设、长期记忆、技能目录或其他归档段。只有路径不等于文件内容，缺件、不支持的类型和容量超限都会明确失败，不自动裁剪或退化为文件名。
- 压缩过程使用普通回复显示器和停止按钮。Web 按网页设置显示前台流式分片或“非流式输出中”，Bot 按自身设置显示前台流式、后台流式字数进度或非流式等待；网页命令与按钮发起的压缩在对应 Bot 当前对话同步，其他对话继续隔离。只有正常完成、非空且通过校验的摘要，才在数据库事务中替换源历史并保存为普通 AI 回复，实时展示与刷新历史使用同一条结果记录。
- **失败、超时、截断和停止均保留原上下文、附件和会话版本，只增加一条模型可见的系统失败提示。** 已收到的分片仅作临时预览，半截摘要不会提交、不会进入后续模型上下文，也不会重置历史界面；失败提示和原始错误继续保留。生成期间出现新消息则拒绝提交旧快照；用户主动清空优先，旧请求不会复活旧历史。
- 「重试压缩」与新压缩使用同一流程：重新读取当前历史并导出，把当前提示词追加到最后。失败后新增的消息也纳入压缩；旧按钮保持兼容。重启不会自动重试收费请求。
- 成功后，旧附件退出自动上下文，磁盘原件和备份保留；摘要受普通历史深度限制，不额外置顶。后续请求保留简短的归档路径入口，必要时可通过 `read-x` 回看。新上传附件和新生成图片继续正常提供。
- 导出或回复投递失败不会撤销已保存的备份或已提交的摘要。`/clear` 开启新的上下文阶段，下一次压缩从该阶段的第 1 段编号；历史、原件、已有压缩记录和定时任务继续保留。旧归档不改写，也不自动恢复旧版本已经物理删除的内容。

压缩指令位于 `prompts/compression.txt`，在「提示词」菜单中名为「上下文压缩提示词」，支持查看、修改、下载和重载。菜单保存和磁盘文件编辑会影响下一次压缩或重试；进行中的请求使用开始时冻结的指令。启动时只升级与旧版内置默认内容完全相同的文件，不覆盖用户自定义提示词。

默认指令要求输出详细交接记录和状态快照，以独立信息点为单位，不限定字数或压缩比例，保留用户要求、修正、禁止事项、参数、路径、已验证结果和未完成事项。实际提供的原生附件可以作为依据，但不允许补造未提供的文件内容、未留存的工具正文或内部思考。提示词及模拟请求测试不能保证真实模型没有摘要遗漏，仍需结合备份核对。

归档保存在 `xgent_storage/exports/日期/唯一目录/`，ZIP 中每个文本文件在同目录都有可直接读取的版本。**压缩模型的冻结快照**继续使用以下文件名，例如完成两次压缩后：

```text
拦截记录.txt
提示词.txt              导出时当前有效的对话提示词
压缩提示词.txt          当次实际使用的压缩指令
1a全局记忆.txt          第一段完整持久化记录
1b附件路径.txt          第一段附件路径、类型、顺序及已有校验信息
1c压缩结果.txt          第一次完成的恢复回复
2a全局记忆.txt          第二段记录，开头包含第一次恢复回复
2b附件路径.txt
2c压缩结果.txt
3a全局记忆.txt          当前尚未压缩的记录
3b附件路径.txt
```

`Nc` 只在该段有完整恢复结果时创建。`1c` 的内容同时作为第二段开头的一条真实回复出现在 `2a` 中，这是有意保留；同一个 `Na` 不额外复制摘要。压缩前生成的 ZIP 保持不变，本次新结果在下一次导出中加入对应 `Nc`。任务状态、各段原始消息及结构化元数据保留在数据库，不再额外导出镜像 JSON、逐轮提示词或 manifest。

ZIP 不复制附件原件，也不嵌入请求中的图片 Base64。摘要不能保证语义绝对无损，因此始终保存原文；归档只含已持久化内容，无法补回过去未入库的 `read-x` 正文。`read-x` 的实现和跨轮持久化行为未改变。

普通对话导出在存在数据时还会生成 `工具调用记录.txt` 和 `思考记录.txt`，供阅读已保存的参数、结果与可见思考，不从 Token 数猜测内容，也不读取引用路径的文件本体。它们不参与压缩或后续模型请求，见 [工具历史与导出](tool-call-mode.md#历史与展示)。

**普通 /export** 则按上下文阶段分组，文件名和 ZIP 条目均按名称排序，例如：

```text
001-已清空-001a全局记忆.txt
001-已清空-001b附件路径.txt
001-已清空-001c压缩结果.txt
001-已清空-002a全局记忆.txt
001-已清空-002b附件路径.txt
002-当前-001a全局记忆.txt
002-当前-001b附件路径.txt
上下文范围.txt
```

每次 /clear 增加一个阶段，压缩只增加阶段内轮次；编号至少三位并统一补零。未压缩尾段仅有 a/b，不编造 c；已清空阶段不混入当前阶段。各段 a 文件中的普通记录不重复、不遗漏，说明文件包含已知清空时间。“已清空”只是退出模型上下文，永久删除的整个会话不会重新导出。旧 ZIP、压缩引用和附件原件不改写。
