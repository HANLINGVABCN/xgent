# Tool call／正则围栏

两种模式只改变模型如何提出工具请求，共用现有执行器、消息投递和历史数据库。全局设置为 `agent_call_mode=toolcall|fence`。Web 输入框生成选项与 Agent 设置页、Bot `/start` 的工具调用选项、CLI 的同一原生菜单均可修改；不需要部署 Web 才能使用 Bot。

新数据库初始化为 Tool call。已有数据库缺少该设置时初始化为正则围栏；已有值保留。恢复旧应用设置时缺少该项也使用围栏，仅导入对话历史不改变设置。切换影响下一次新请求；同一连续执行、排队接入、等待表单及提交恢复固定原调用模式与提供商／模型。

## 执行与兼容

- OpenAI Chat Completions、OpenAI 兼容接口、Gemini／Vertex、Claude 的非流式、前台和后台流式均接收原生调用。HTTP 地址、API Key、代理、连接池与用量记录继续沿用现有配置。
- Tool call 工具入口独立命名：执行命令 `exec_command(command)`，交互终端 `start_terminal`／`terminal_input`／`close_terminal`，文件读取、修改、写入、二进制写入、交付使用 `read_file`／`edit_file`／`write_file`／`write_binary`／`send_file`，检索与代码分析使用 `search_files`／`inspect_code`，联网使用 `search_web`／`fetch_urls`，生图、表单和收尾使用 `generate_media`／`ask_user`／`finish_task`。工具定义与提示词不再用旧协议函数名；后台执行器继续复用，界面的既有协议标识保留。
- Tool call 接收完整参数并按 schema 校验后才执行，同批工具保持顺序。命令、文件内容及编辑旧／新串保留原始空格、缩进和换行。一次响应中所有调用先完成校验，错误或截断参数不执行。
- 流式参数按调用位置拼接，支持合法的分片函数名；同一位置的 ID／函数名冲突、无效索引、重复开始或结束后的参数分片会阻止整批调用。调用编号转换只发生在请求副本里，保留原始编号和参数；外来长编号、特殊字符及跨运行重复编号转换为目标接口兼容且相互匹配的调用／结果编号。
- 每个回合只使用选中的执行入口。Tool call 不执行正文中的围栏；围栏模式不执行原生调用。完成调用按运行、响应、调用 ID 对应结果，重复事件不重执行。
- `ask-x` 仍在 Telegram 内填写或在原浏览器内嵌表单填写。表单后的调用暂停；提交后补齐该调用结果再继续后面的工具。取消后剩余调用记为未执行，交回模型收尾。用户密钥仍只交给现有私密存储，模型取得变量名。
- `over-x` 沿用原有适用范围和成功要求，省略的仅是下一次模型请求。执行事实及调用关系仍保存；包含表单的同批响应不会因提交表单而重新获得免回传资格。
- Agent 开关独立决定是否允许工具。模型明确拒绝 `tools` 等能力时提示手动切换围栏；不自动切换，不把超时、限流当成接口不支持。

`prompts/toolcall_addon.txt` 只用于 Tool call，`agent_addon.txt` 只用于正则围栏，菜单分别标为“Tool call 模式提示词”和“正则围栏模式提示词”。两份文件独立编辑，任何旧文件修改都不会使它混入另一模式。用户人设、全局说明、记忆与技能索引仍正常组合；通用技能和附件提示使用当前模式的实际工具名。Tool call 文件为空或无法读取时明确报错，不退回旧围栏说明。

Tool call 的具体功能和参数由 API 工具清单说明，追加提示词只保留授权、执行顺序、原文保留、实际环境验证、失败重试、密钥与收尾规则。精简默认模板从 2805 字符降至 922 字符，减少约 67%；这是该文件的长度减少，不是整次请求 Token 或费用的同比降低。未修改过的旧详细模板自动备份后更新，用户改过的模板保留。

每次 Tool call 请求继续提供全部 16 个工具，不按需隐藏工具。执行结果附加的操作说明使用本回合固定模式的函数名或围栏协议名；只改系统生成的说明，不替换命令、文件、网页或原始错误中的文字。已有用户提示词和已保存记录不改写。

启动时仅更新内容与上一版默认模板完全一致的 Tool call／全局说明，更新前保留 `.before-mode-split-*.bak` 原文件备份；用户修改过的文件不覆盖，也不猜测其中哪些句子应迁移。新版默认全局说明按当前会话隔离描述历史，空闲提醒明确此次没有执行工具且不改变 Agent 开关，Agent 关闭时不要求修改、读取或发送服务器文件。旧函数名称只用于读取已有结构化历史，不接受为新的执行请求；无需数据库迁移。

## 历史与展示

工具调用和结果在现有消息元数据中保存，原回复正文仍只有模型实际返回的正文。纯工具响应展示命令卡片，不生成空白正文；工具输出继续独立，Bot 的 50行／3200字符预览、状态点与存档路径保持原规则。最终回复的详情仍只附一次。

`write_file` 和 `write_binary` 只写入磁盘，返回实际路径、大小及覆盖状态；界面显示一行写入结果，不自动上传文件。用户需要原件时用 `send_file` 交付。正则围栏模式的 `file-x`／Base64 写入采用相同规则，原有文件仍保留。

Web 刷新重建原生调用卡片时读取保存的调用参数；文件发送保存实际附言和消息关联，图片作为文件发送时仍显示文件卡片。文件名与发送说明使用贴近附件的 11px 灰色小字，不在刷新后替换成重复路径。连续回复按运行和对话回合分别判断作者，补齐历史标识不会产生额外头像。旧回复定稿只结束自己的生成阶段，表单消息保留按钮状态，不因收尾读取缺失字段而中断。

保存完整调用和结果的历史在下一次用户请求或切换模型时，仍按目标 API 的原生调用／结果格式转换；不再把旧调用拼成 AI 正文，避免模型模仿历史文本打印命令。匹配包含运行、响应和调用 ID，重复 ID 不串结果。缺少完整关联的调用仅作为标注过的历史资料传入，原有 AI 正文单独保留，不补造执行结果。压缩后的普通文字也不反推工具调用。

必要的提供商续接字段仅在匹配的提供商、模型和运行中使用，跨运行或模型转换时不携带。原生图片或二进制工具结果完整交回模型；OpenAI Chat Completions 不接受工具消息里的原生附件时，附件作为相邻输入交付。历史转换只读取已有结构化字段，不匹配 AI 正文来执行命令或追加异常提示。工具留存仍由原有设置控制。

记忆深度仍决定普通消息窗口；若窗口边界包含原生工具记录，则额外补齐同一响应的调用批次及全部已保存结果分片。保留在窗口外的原生附件也携带对应调用。关联读取限定当前会话、未撤回记录、当前有效上下文及该次读取的记录上界，不带入其他会话或后来消息。缺少记录不补造结果；上下文超限继续明确失败，压缩仅由用户手动触发，不自动压缩或裁剪来强行调用模型。

表单暂停与恢复沿用同一个展示分组，虽然实际运行记录仍分别保存，Web 后续回答不重复显示头像。用户的新提问仍建立新的展示分组；思考的内容、折叠与复制规则不变。

调用参数与结果关联进入历史、导出和分支；读取历史不执行工具。用量沿用接口实际返回值，包括生成工具参数的用量。Tool call 通常仍包含“提出工具请求 → 执行 → 请求模型分析结果”两次模型调用，不承诺固定节省比例。

普通会话导出保持各段 `a全局记忆.txt` 的原始结构，另有数据时增加 `工具调用记录.txt` 和 `思考记录.txt`。前者按调用列出参数原文和对应结果，缺少结果或成功状态时明确标注；编码本体不在可读文件里重复打印，原始工具记录仍保留。后者只导出已保存的可见思考、状态及已记录耗时，无数据不产生空文件、不根据 Token 猜测。两个可读文件仅供阅读，不参与模型请求或压缩输入，导出不会读取引用路径的文件本体。

诊断沿用现有轮转及缓冲受限的 JSONL 日志，`tool_request` 记录实际发起的客户端请求和完整工具清单，`tool_response` 记录收到的原生调用数量及结束状态，`tool_parse` 记录校验结果，`tool_dispatch` 区分分派与重复跳过，`tool_execution_result`／`tool_result_recorded` 记录真实返回和保存关系。通过会话、运行、响应和捕获 ID 关联，分派不冒充执行成功，不扫描正文判断执行；SDK 内部重试不冒充额外模型回合。诊断不另存命令参数、输出或密钥，写入失败不改变执行结果，原有报错显示及字数预算保留。

## 仓库与验证

默认仓库及更新源为公开的 `HANLINGVABCN/xgent` 的 `main`，克隆和默认更新无需 Token。`xgent-test` 保持私有，读取测试源时使用 `UPDATE_GITHUB_TOKEN`，需要该仓库 Contents 读取权限。明确配置的 `UPDATE_ZIP_URL` 或安装脚本仓库参数仍可覆盖默认源；Token 不写入代码或下载提示。

隔离测试覆盖五种接口与三种生成方式、连续用户请求的历史重建、深度边界和留存附件的关联补齐、外来与重复编号、流式冲突、模式专属结果说明、原始参数逐字保留、实际调用诊断、可读导出、可见思考、表单提交与取消、停止、原始错误和原有围栏。传输模拟只用于验证请求与执行链路，不代表真实模型质量、实际 Token 节省或 Telegram 客户端显示验收。

服务器不部署、不修改、不重启；修改完成后以临时标签运行完整 CI，通过后发布两个现用仓库的 `main`。
