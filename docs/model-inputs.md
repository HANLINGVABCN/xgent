# 模型输入与容量参考

[返回使用文档](README.md) · [返回项目首页](../README.md)

Web 在「设置 → 模型与技能」中管理提供商，可用当前表单的接口地址和密钥拉取候选模型。选择模型后，可分别设为对话模型或媒体模型；卡片上的「当前对话」「当前媒体」显示已生效的模型。下拉框的候选选择本身不会改变已生效模型。纯 Web 部署也提供这些管理能力。

普通聊天附件与服务器上传的区别见 [文件入口](file-ingress.md)。下面的媒体示例采用正则围栏模式；Tool call 模式使用 `generate_media(prompt, files)`，对应参数由实际工具定义提供，见 [双模式说明](tool-call-mode.md)。

## 媒体参考文件

纯生成兼容原有写法，也可以用 `prompt:` 显式给出指令：

```media-x
<<BEGIN_gen_garden_1577
Please generate an image of a quiet autumn garden.
<<END_gen_garden_1577
```

单文件编辑：

```media-x
<<BEGIN_edit_lollipop_7321
file: /data/source.png
prompt: 把图中人物手里的棒棒糖换成冰淇淋，其他内容保持不变。
<<END_edit_lollipop_7321
```

多文件参考：

```media-x
<<BEGIN_edit_reference_1577
file: /data/source.png
file: /data/icecream.png
prompt: 把第一张图中人物手里的棒棒糖换成第二张图里的冰淇淋。
其他内容保持不变。
<<END_edit_reference_1577
```

路径必须换成**运行服务器上已存在的普通文件的绝对路径**，不限于上传目录，只能读取进程本身有权限访问的文件。支持中文、空格、成对外层引号，以及 Windows 路径，例如 `file: "C:\images\参考 图.png"`；不能用浏览器所在电脑的路径代替服务器路径。不接受 URL、相对路径、通配符或目录扫描。

- 首个非空行是 `file:` 或 `prompt:` 时启用新格式。`prompt:` 必填，`file:` 可省略或重复，必须全部放在 `prompt:` 前。字段名周围可有空白，冒号兼容 `:` 和 `：`。
- `prompt:` 后的全部内容原样作为多行指令，不再解析其中的字段或协议。文件顺序与声明一致，同一路径重复出现也不会去重。
- 后端完整读取指定原件并构造模型输入，无需模型先执行 `read-x`。图片识别真实格式并校验，文本完整解码，其余文件使用原生二进制输入。源文件不覆盖、不转码、不截图替代、不截断，也不继承 `read-x` 的 8 MB/512 KB 限制。
- 请求只带本次指定文件、生成指令和媒体生成说明，不带聊天历史、人设或其他已关联附件。文件内容属于参考资料，不是系统指令。

| 接口格式 | 可表达的参考输入 |
| --- | --- |
| OpenAI / OpenAI 兼容 | 图片、全文文本、PDF、WAV、MP3 |
| Claude | 图片、全文文本、PDF |
| Gemini / Vertex | 图片、全文文本，以及原生二进制文件（含模型支持的文档、音频、视频） |

以上是接口表达范围，不是对模型能力的保证；模型或兼容网关不支持某种输入时会保留接口错误。仍使用现有对话端点，不切换图片编辑端点，也不新增文件上传服务。任一文件缺失、不可读、图片损坏、类型不支持或已知限制超出时，在调用前明确失败并报告文件序号、路径与原因，不会发送删减后的请求。输入文件不会新增普通聊天附件关联，原先已关联的附件不变；生成图片仍先保存再投递，继续进入后续上下文，Web 图文合并和下载行为不变。

围栏模式的完整格式见 [agent_addon.txt](../prompts/agent_addon.txt)。部署保留了自定义提示词时，应在提示词菜单核对其格式；用户自定义内容不会自动覆盖。输入按原始字节、全文和顺序构造，不代表模型一定能精确完成编辑，仍需使用支持对应能力的媒体模型。

## 模型容量配置

模型列表接口提供的容量和图片能力元数据会自动保存；不会仅凭模型名称猜测容量。也可以通过 `BotMemoryDB.set_config("model_request_limits", value)` 写入 SQLite `config` 表，并重启服务加载。`value` 按 `提供商名称/模型ID` 设置，下面的数值仅为格式示例，应替换为所用接口的真实限制：

```json
{
  "provider-name/model-id": {
    "context_window": 128000,
    "max_output_tokens": 8192,
    "output_reserve_tokens": 4096,
    "max_images": 100,
    "max_request_bytes": 20971520,
    "supports_images": true
  }
}
```

各字段均可省略；未知限制不要填 `null` 或猜测值。另支持 `max_input_tokens`（独立输入上限）和 `image_token_budget`（每张图的保守估算值）。已知容量时默认预留最多 4096 输出 token，并受已知输出上限约束；思考参数抬高输出预算后会再次按最终请求检查。配置表示服务端限制，只用于拒绝无法完整发送的请求，不用于裁剪内容。

`media-x` 使用默认媒体模型对应的配置，不沿用聊天模型的容量或图片能力。另支持 `max_files`（本次显式输入位置数，可为 0，重复路径也计数）与 `max_file_bytes`（单份输入原件的字节上限）。原生 PDF、音频、视频等文件无法可靠换算 token 时，只预检可估算的文字/图片部分与输出预算，原生文件的实际容量交接口校验；不会把忽略二进制的估算说成完整容量保证。请求体上限仍按包含全部原件 Base64 的最终请求检查。
