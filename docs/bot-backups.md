# 备份模式与 Bot 导入导出

## 三种压缩模式

| 模式 | 文件格式 | 行为 |
| --- | --- | --- |
| ZIP · 通用 | `.zip` | 保留原来的 Deflate 6 级压缩与兼容性 |
| Zstd · 快速 | `.tar.zst` | Zstd 1 级流式压缩，优先速度；读取和写入有界，不把整个备份放进内存 |
| XZ · 高压缩 | `.tar.xz` | LZMA2 9 级加强模式，字典控制为 8 MiB，优先压缩体积 |

压缩率与耗时取决于实际数据，不承诺每个文件绝对最快或最小。Web 的估算采用对应编码器取样。旧 `.tar.gz` 包仍可读取，已有显式 TAR.GZ 导出调用保留；Web 当前选择只显示上述三项。

新增 Python 依赖 `zstandard`，更新代码时同步安装 `requirements.txt`。导入仍检查文件清单、路径、哈希、Zstd 校验和与 SQLite 完整性；不调用 shell 解压，不使用 `extractall`。

独立迁移工具未安装第三方依赖时仍能处理 ZIP、XZ 与旧 TAR.GZ；选择 Zstd 时明确提示补齐依赖，不阻塞旧实例的迁移。

## Bot 原生菜单

`/start → 更多 → 下一页 → 导出数据／导入数据`。

导出数据显示三个模式按钮。选择后创建一致的数据库快照，打包全部实例数据、提示词、文件及命令输出，再通过现有文件投递链路交付；备份列表也保留该文件。源码、公共技能、缓存、备份包自身和 `server_assets/` 继续按原规则排除。

导入数据直接显示服务器上已有的备份，超过六项分页。点击所选文件后先完整校验，再自动备份当前数据，交给本地恢复协调器导入和重新启动服务；不打开 Web App。导入通知提供“查看导入结果”，重启后可读取真实完成、失败或回退状态。

一次菜单选择使用固定的请求 ID，重复按钮不重复打包、发送或启动导入；旧列表按钮不能选择新列表的文件。备份任务结果按聊天归属校验。

## `.env` 与身份保留

Bot 默认导出全部实例数据，**整份 `.env` 排除**，独立分类的环境记录也不写入。Bot 导入旧包时，即使包内有 `.env` 或分类环境记录，也保留本机原文件；Bot Token、授权用户 ID 和其他 `.env` 变量不变。

不含环境的包会记录该范围，之后经 Web 恢复时也默认保留目标 `.env`。数据库里的 API 密钥、Web 登录配置等仍属备份数据，菜单明确提示保管。Web 原有按分类选择和环境导入行为继续使用同一服务。

不含环境的整包使用备份清单 v3，旧版导入器会拒绝该版本，避免把缺少 `.env` 误解释为清除本机环境。ZIP 编码仍保持原模式；新版继续读取 v1／v2 旧包。数据库本身不增加迁移。

## 两端独立

Bot 菜单直接调用本地备份、校验、恢复服务与原生文件发送，不依赖 Web 开关、网页密码、HTTPS 地址或 Cloudflare。Web 原有备份页面不依赖 Telegram Token。服务恢复由项目内 `install.sh` 和已有协调器执行。

`/export` 保留当前对话记忆导出的原用途，更多设置中的“导出数据”是实例备份。

## 验证

自动测试覆盖三种压缩格式、旧包读取、重复点击、服务器备份列表、Bot 独立投递、`.env` 原字节保留、分类环境排除、Zstd 校验和与路径拒绝、Web 选择与估算。Bot API 使用固定测试返回，导入启动采用模拟；实际文件恢复在隔离目录验证。未在用户服务器导入、部署或重启。
