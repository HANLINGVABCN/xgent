# 网页附件排队

此前网页在有待发附件时关闭排队资格，上传入口又尝试获取运行中的对话执行锁，因此生成期间带附件的消息无法发送。

新版上传原件后把文件引用与说明保存到现有消息队列。待发条目显示文件名，可取消或取回；当前对话的安全接入点仍由既有队列调度器决定。只有领取条目时才创建正式用户附件记录，完整附件上下文仍由原来的 `build_model_conversation_history` 组装，未领取的文件不会提前交给模型。

取消或取回将文件引用恢复到服务器附件草稿，保留原件、说明、选择顺序以及附件／仅路径上传模式。恢复与队列状态变化在同一事务完成；重复上传标识返回同一条目，上下文版本变化时拒绝本批接纳并保留浏览器文件。8 MiB 以上仍走原有分块传输，分块和普通 multipart 都保留排队及版本参数。

数据库队列表新增 `metadata` 字段，原文字条目的默认值为空对象。模型请求格式、对话上下文规则、现有队列的停止／暂停／恢复和 Telegram／CLI 接入保持原服务实现。配置文件录入等管理状态继续使用原入口。

验证：`tests/test_attachment_queue.py` 使用真实原件与模拟模型请求检查忙碌接纳、模型不可提前读取、重试去重、混合文件顺序、取消取回和只发送一次；`tests/test_message_queue_browser.py` 检查真实 multipart 参数与生成期间的发送按钮；原文件、分块、附件恢复与文字队列回归继续运行。
